# Android Builder 0.3
This integration milestone retains local HTML APK export (website/network option disabled by default). Android ZIP review lists permissions from the source manifest; libraries and flavors can contribute additional declarations. Six optional permission choices add declarations to the working copy of a native project. They do not install functionality or grant Android runtime access.

A single-owner HTTP gateway (private_build_service.py) accepts a conventional Gradle Android ZIP and returns a debug APK or AAB. The APK uses HTTPS only, will not follow redirects, and asks for confirmation before transferring input. The gateway intentionally binds to loopback; deploy behind a configured TLS reverse proxy. Use a strong scoped access key, not the OpenAI key. Do not publish this gateway as a general website. Build only on a dedicated runner with isolation independent of credentials; the repository test runner is for synthetic projects only. The container adapter requires a verified, pinned build-worker image with Java, Gradle, Android SDK 35 and warmed dependencies, and an entrypoint for the native build script. Review image, mounts, timeouts, quota and cleanup before exposing a private deployment. Neither the server nor its required worker image is deployed by the repository.

The optional AI route calls the OpenAI Responses API to draft self-contained HTML. Configure BUILDER_AI_MODEL and a scoped OPENAI_API_KEY on the server, not in Android or in a chat. Test mode intentionally does not make real OpenAI requests. AI output needs review and verification. Dictation and native AI generation are not present. The APK and AAB from the native ZIP test are debug builds, not Play release artifacts.
